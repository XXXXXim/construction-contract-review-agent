# P7. 회고 (KPT)

> 기간: 2026-11-04 ~ 11-08 · 커밋 15개 · 테스트 74개 (회고 작성 시점 기준. 이후 set-public·FR-19 를 더해 2026-11-10 현재 테스트 103개) · 실측 모델 claude-sonnet-5-5

## 결과 요약 (숫자로)
- set-v2(정답 24개)에서 baseline → v2: **Recall 0.92 → 1.00, Precision 0.81 → 1.00, 근거 조항 정확도 0.00 → 1.00**
- 대가: 계약서당 입력 토큰 **43.6k → 257.9k (약 5.9배)**
- v1 → v2 개선은 전부 **규칙 레이어**에서 나옴 (누락 2건, 오탐 2건 해결). 근거 검증은 폐기 0건으로 **효과 미관측**
- baseline 이 기억으로 적은 하도급법 인용 21건 중 **5건이 원문과 불일치** (원문 대조로 확인)
- 원래 MVP 마감(11/7 23:00)은 **넘겼다**. 실제 LLM 평가는 11/8 완료

## Keep (계속할 것)
| 무엇 | 왜 효과가 있었나 |
|---|---|
| **원문 출처 강제** (기준값마다 원문 인용 + 존재 검증 테스트) | 내가 법령 숫자를 틀릴 위험을 구조적으로 없앴고, baseline 의 인용 오류를 판정하는 기준이 됐다 |
| **평가 하네스를 기능보다 먼저** | 구성을 바꿀 때마다 같은 잣대로 비교할 수 있었다. "v2 개선은 전부 규칙 덕"이라는 결론도 하네스가 있어서 나왔다 |
| **나쁜 숫자도 그대로 기록** | risk_match 하락, 근거 검증 효과 0 을 숨기지 않아서 오히려 설명할 거리가 생겼다 |
| **실제 실행 전 드라이런** | 가짜 키 드라이런으로 `temperature` 거부 버그를 잡아 150회 호출 낭비를 막았다 |
| **데이터 수정은 별도 버전** (set-v1 유지, set-v2 추가) | "숫자를 위해 평가셋을 고쳤다"는 의심 없이 버그 효과를 분리해서 보였다 |
| **결과 보기 전에 채점 기준과 예상을 커밋** (set-public) | 검색 약점·규칙 0적중을 미리 적어둬서, 결과를 보고 기준을 바꿨다는 의심이 생기지 않았다 |

## Problem (문제였던 것)
| 무엇 | 결과 | 근본 원인 |
|---|---|---|
| **기획·요구사항·준비물 단계 생략** (설계부터 시작) | API 키 부재를 M0 에 언급만 하고 넘어가 M4 에서 막힘 → MVP 마감 초과 | 준비물을 "확인하는 게이트"가 없었다 |
| **평가 데이터 생성기 버그를 결과를 보고서야 발견** | set-v1 의 오탐 3건이 사실은 데이터 결함 (내부 조문 참조 58개 중 54개 어긋남) | 생성된 데이터의 **불변식**(참조 일관성)을 검사하는 테스트가 없었다 |
| **캐시와 시간 측정이 충돌** | v1·v2 처리 시간 비교 불가. 재실행이 첫 실행 결과 파일을 덮어씀 | 측정 목적(비용 절감 vs 시간 측정)을 실행 설계 때 분리하지 않았다 |
| **평가 하네스 자체에 테스트 없음** | 수정 중 `make eval` 이 KeyError 로 깨졌는데 테스트는 통과 | "평가 코드도 코드"라는 걸 늦게 적용 |
| **추정치를 확인 전에 보고** | "참조 114개 중 89개 어긋남"을 말했다가 58개 중 54개로 정정 | 숫자를 말하기 전에 계산 방법을 검증하지 않았다 |
| **Anthropic 키를 세션에 저장하지 못함** | 보스 맥에서 실행하는 방식으로 우회 | 환경 제약(예약 호스트)을 P3 에서 확인하지 않았다 |
| **실제 문구에서 파이프라인의 탐지 우위가 없음** (set-public, baseline 도 5/5) | "조항 분할이 탐지를 높인다"는 주장은 합성셋에서만 성립 | 평가셋이 "노골적 특약"과 "미묘한 숫자 변경"을 섞어 담지 못했다 |

## Try (다음에 시도할 것)
1. **P3 준비물 게이트를 첫날에 실제 명령으로 통과**한다. 키·데이터·네트워크·실행 위치(세션 vs 로컬)를 확인하기 전에는 구현을 시작하지 않는다.
2. **합성 데이터에는 불변식 테스트를 같이 만든다.** 예: 내부 참조가 모두 존재하는 조항을 가리킨다, 정상 조항은 원문과 같다.
3. **비용 측정 실행과 시간 측정 실행을 분리**한다. 시간은 캐시를 끄고 별도로 한 번 잰다. 결과 파일은 덮어쓰지 않는다(append-only).
4. **숫자를 보고하기 전에 그 숫자를 만든 스크립트를 남긴다.** 말로 먼저 하지 않는다.
5. 평가셋이 너무 쉬우면(검색 hit@3 1.00) 비교가 안 된다. **문장을 다시 쓴 어려운 변형**을 처음부터 섞는다.
